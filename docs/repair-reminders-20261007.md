# 수선 미확인 메시지 리마인더 · 발송 실패 알림

## 운영 규칙

- 마지막 실제 대화 메시지가 관리자 작성이고 24시간 이상 읽히지 않은 열린 수선 티켓에 적용합니다. 시스템 상태 안내는 실제 대화 순서를 바꾸지 않습니다.
- 국내(KR) 연락처에 티켓당 총 1회만 문자로 안내합니다. 기존 열린 티켓도 5분 주기의 검사에 포함합니다.
- KST 09:00 이상 21:00 미만에만 발송하며, 그 밖의 시간은 다음 09:00으로 미룹니다.
- 발송 직전 읽음, 고객 답장, 새 관리자 답장, 종료·취소·거절, 템플릿 활성화, 현재 연락처를 다시 확인합니다.
- 문자 내용: `[오알룸] 확인이 필요한 수선 메시지가 있습니다.` 다음 줄에 해당 티켓 링크를 넣습니다. 길이에 따라 기존 SOLAPI 규칙으로 SMS/LMS가 결정됩니다.
- 고객에게 요청을 보낸 기록은 알림 내역 정리와 별개로 보관합니다. 전달 여부가 불확실하거나 실패한 리마인더를 자동 또는 수동으로 재발송하지 않습니다. 다른 문자·이메일로 추가 리마인더를 보내지도 않습니다.
- 발송 전에 조건이 사라지면 대기 중 안내를 취소합니다. 아직 발송 시도가 없었다면 이후 새 미확인 대화가 다시 대상이 될 수 있습니다.

## Notification Admin

운영 DB에 수선 리마인더 템플릿은 없고 워크숍 일정 리마인더만 있었습니다. 기존 워크숍 템플릿을 유지하고 아래 두 항목을 추가·활성화했습니다.

- `ticket.unread_reminder` / 문자 / 수선 미확인 메시지 리마인더
- `notification.delivery_failed_admin` / 이메일 / 전체 메시지 발송 실패 알림

수선 리마인더만 추가 문자 제한에서 허용하고, 다른 비활성 문자 알림은 그대로 둡니다.

## 실패 감지

수선·주문·워크숍 공통 대기열, 이전 수선 이메일 대기열, 인증코드·비밀번호 재설정, 워크숍 결제 요청, 주문 취소 승인 이메일을 포함합니다.

API 오류, 네트워크 오류, 타임아웃과 함께 SOLAPI의 HTTP 200 응답 내 접수 거절도 감지합니다. 접수된 문자는 SOLAPI 결과 조회, 이메일은 Resend 결과 조회로 전달 실패·반송을 확인합니다. 최초 조회는 5분 후, 미확정 결과는 15분 간격으로 재조회합니다. 7일간 최종 결과가 없으면 확인 필요 알림을 남깁니다. 조회 권한 오류도 별도 관리자 알림을 생성합니다.

실패 건당 관리자 이메일을 한 번 생성합니다. 알림 내역을 정리해도 중복 알림 방지 기록을 유지합니다. 수신자는 `NOTIFICATION_FAILURE_EMAIL`, `REPAIR_ADMIN_EMAIL`, `studio.oalum@gmail.com` 순으로 결정하며 테스트 이메일 설정으로 전환하지 않습니다. 이메일에는 종류, 가려진 수신자, 기록 ID, 오류와 알림 관리 링크를 넣습니다. 인증코드·고객 메시지 본문은 넣지 않습니다.

관리자 알림 이메일 자체의 실패는 새 실패 알림을 생성하지 않고 기존 이메일을 재시도합니다. 이메일 서비스 자체가 중단되면 관리자 이메일도 즉시 전달할 수 없으며, 대기열에서 최대 24회 재시도합니다.

## 검증

새 동작 테스트 28개가 통과했습니다. 전체 167개 중 166개가 통과했고 `repair submissions allow enough retries to recover from transient failures` 1개는 기준 커밋 `31cd98f`에서도 동일하게 실패합니다. 기존 코드의 신청 횟수 제한 6회와 테스트의 기대값 20회가 다른 문제이며 이번 변경에 포함하지 않았습니다.

배포 빌드와 서버 함수 빌드를 검증합니다. 운영 DB에는 다른 미적용 변경을 함께 적용하지 않고 `0043_repair_reminders_and_failure_alerts.sql`만 명시적으로 적용합니다.
