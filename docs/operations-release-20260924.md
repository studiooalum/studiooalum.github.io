# 2026-09-24 운영 개편

## 워크샵

- 원데이클래스: 날짜와 시간대를 선택하고 신청자가 전체 인원 요금을 결제합니다. 다른 신청자의 추가 합류는 받지 않습니다.
- 오알룸 워크샵: 관리자가 1개 이상의 회차를 등록합니다. 표시 가격은 1인의 전체 과정 가격이며, 신청 인원에 따라 총액을 계산합니다.
- 맞춤 워크샵: 목록에 단일 문의 항목을 유지합니다. 관리자는 대표 이미지와 접수된 문의의 상태/내부 메모를 관리합니다. 문의 자체로 예약이나 결제를 확정하지 않습니다.
- 원데이 요금은 관리자 입력값을 사용합니다. 2~4인 별도 요금을 입력하지 않으면 1인 기본 가격에 인원을 곱합니다. 5인 이상은 1인 기본 가격을 적용합니다.
- 원데이 시간대는 관리자에서 추가할 수 있습니다. 한국 시간 기준 당일/과거 날짜, 차단 일정, 이미 예약된 시간대는 신청할 수 없습니다.
- 기존 예약, 결제, 그룹 데이터는 삭제하지 않습니다. 신규 그룹 생성 경로만 제거하고 기존 기록의 취소/환불 호환성을 유지합니다.

## 결제 설정

Cloudflare Pages 프로젝트는 `studiooalum`입니다. 다음 값은 서버 설정으로 등록합니다.

| 설정 | 용도 |
| --- | --- |
| `TOSS_CLIENT_KEY` | 토스 결제위젯 공개 클라이언트 키 |
| `TOSS_SECRET_KEY` | 같은 상점과 모드의 서버 시크릿 키 |
| `TOSS_PAYMENT_VARIANT_KEY` | 결제수단 UI 키, 기본 `DEFAULT` |
| `TOSS_AGREEMENT_VARIANT_KEY` | 약관 UI 키, 기본 `AGREEMENT` |

- 테스트 키는 `test_`, 라이브 키는 `live_` 모드로 서로 일치해야 합니다. 키가 없거나 혼용되면 결제를 차단합니다.
- 승인 API는 저장된 주문 금액과 토스 조회 결과를 검증합니다. 브라우저에서 전달한 상품 가격은 사용하지 않습니다.
- 결제/취소 요청에는 멱등 키를 사용합니다. 승인 중인 주문과 예약은 다른 결제 요청이나 취소가 덮어쓰지 못하도록 보호합니다.
- 토스 웹훅 URL: `https://studiooalum.com/api/webhooks/toss`. 요청 본문만 믿지 않고 토스 서버에 결제 상태를 조회합니다.
- 수선은 최종 금액과 결제 대기 상태가 등록되면 권한이 확인된 Repair Ticket에서 결제를 시작합니다. 문자/이메일에는 기존 Ticket 링크를 안내하고 별도 공개 결제 토큰을 노출하지 않습니다.
- 수선 결제 완료는 서버에서 입금 확인일과 Ticket 메시지에 반영합니다. 발송 정보 입력은 관리자가 별도로 진행합니다.
- 실결제 또는 실제 환불은 이번 검증에서 실행하지 않았습니다. 운영에는 아직 토스 키 등록이 필요합니다.

### 해외 카드

현재 주문/정산 통화는 KRW입니다. 해외 발급 카드의 원화 결제는 토스 해외 카드 추가 계약과 카드사 심사 후, 토스 결제 관리자에서 해당 결제수단을 활성화하면 됩니다. 필요하면 해당 UI의 `variantKey`를 설정합니다.

USD 등 외화 정산과 PayPal은 별도 MID/계약 및 상품·배송 정보 계약이 필요하므로 이번 KRW 구현에 포함하지 않습니다. 키만 등록한다고 해외 카드 계약이 자동 활성화되지는 않습니다.

공식 문서: https://docs.tosspayments.com/guides/v2/learn/foreign-payment

## 알림

- 공통 이메일 대기열: 쇼핑 결제/환불/배송, 워크샵 신청/결제/취소/환불, 맞춤 문의, 수선 Ticket과 결제 안내.
- 워크샵 회차 전날 안내와 최소 인원 미달 관리자 알림, 미결제 예약 만료를 정기 처리합니다.
- 기존 `studiooalum-repair-notifications` Worker가 보호된 `/api/repairs/notifications/process`를 호출합니다. 같은 작업에서 승인 중 결제를 재조회합니다.
- 기존 수선 SMS 4개 단계는 그대로 유지합니다. 새 SMS 템플릿은 비활성입니다. `ADDITIONAL_SMS_ENABLED=false`가 추가 문자 활성화를 차단합니다.
- 운영 이메일에는 기존 Resend 설정을 사용합니다. 정기 작업의 `REPAIR_NOTIFICATION_CRON_SECRET`은 Pages와 Worker에서 일치해야 합니다.
- 문의 개인정보와 해당 알림 기록은 문의 종료 후 1년 경과 시 정기 정리합니다.

## 보안 및 데이터

- 관리자 세션은 서버 저장 토큰과 12시간 만료를 사용합니다. 배포 후 기존 세션은 다시 로그인이 필요할 수 있습니다.
- 비밀번호 회원가입은 이메일 인증번호 확인 후 계정/기존 주문을 연결합니다.
- Account 프로필 이미지는 `0039_account_profile_image.sql`로 추가한 비공개 R2 키만 D1에 저장합니다. 이미지는 인증된 본인만 `/api/auth/profile-image`에서 조회·교체할 수 있습니다.
- 공개 신청/로그인 API에 요청 제한, 변경 요청 출처 검사, JSON 크기 제한을 적용합니다.
- 개인정보 API는 `private, no-store`로 응답하고 서버 내부 오류 상세를 공개하지 않습니다.
- 공개 R2 API는 워크샵/뉴스레터/수선 갤러리만 허용합니다. 신청 사진과 Ticket 첨부는 기존 인증 경로로만 조회합니다.
- 운영 D1의 외래키 검사와 `quick_check`는 변경 전 정상으로 확인했습니다.
- 거래·수선 이력, 이전 알림 대기열과 호환 테이블은 보존합니다. 테이블 존재만으로 불필요한 데이터라고 판단해 삭제하지 않습니다.

## 배포 및 검증

- 전체 검증: `npm run verify`.
- 브라우저 검증: 설치된 Playwright를 지정해 `PLAYWRIGHT_MODULE=/path/to/playwright/index.mjs node tests/storefront-browser.mjs`를 실행합니다. 로컬 호스트에서만 동작합니다.
- 검증용 Pages 서버는 별도 `--persist-to .wrangler/release-check-20260924`를 사용합니다. 기존 로컬 DB를 초기화하지 않습니다.
- 화면 번들은 `npm run build:storefront`로 생성합니다. 현재 배포 HTML은 `*-20260924` 진입 파일을 사용합니다.
- 운영 순서는 D1 전체 백업, 확인된 추가 마이그레이션만 직접 적용, Pages 배포, 운영 점검입니다. `0035`~`0038`과 `0039`는 각각 백업 복사본 검증 후 운영에 적용되었습니다. 비어 있는 기존 마이그레이션 이력에 전체 체인을 실행하지 않습니다.
- 운영 의존성 `npm audit --omit=dev` 결과: 보안 권고 0건. 아직 운영에 사용하지 않는 `apps/web`의 Next.js도 호환 패치로 갱신했습니다.
- 브라우저에서는 원데이 시간/인원/총액, 전체 회차, 맞춤 문의, 관리자 처리, Ticket 결제와 가로 넘침을 검증했습니다. 결제사는 모의 응답이며 이미지 미리보기 도구 확인은 생략했습니다.
