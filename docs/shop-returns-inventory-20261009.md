# Shop 반품·환불 및 단일 에디션 재고

## 고객과 관리자 흐름

- 주문 확인 단계의 기존 직접 취소는 유지합니다.
- 배송 준비·배송 중·배송 완료 이후에는 계정 또는 비회원 주문 조회에서 사유를 선택합니다. 단순 변심, 사이즈·착용감, 하자, 오배송, 기타를 지원하며 기타는 상세 설명이 필수입니다.
- 요청은 주문 전체에 적용됩니다. 일부 상품만 반환하는 요청은 고객센터에서 별도로 처리합니다.
- 관리자 `/admin`의 반품·환불 대기 목록에 표시되며 고객과 관리자 이메일을 대기열에 등록합니다. 관리자 이메일은 해당 주문을 열고, 관리자 로그인을 거쳐 승인합니다. 이메일 링크만으로 결제를 취소하지 않습니다.
- 발송 전: 승인 시 실제 결제 금액 전액 취소.
- 발송 후: 회수 주소·방법을 입력하여 승인 → 회수 대기 → 상품 회수와 상태 확인 체크 → 환불 실행.
- 발송 후 단순 변심·사이즈 반품은 실제 결제 금액에서 4,000원 공제가 기본값입니다. 관리자가 면제할 수 있습니다. 하자·오배송은 공제 불가입니다. 기타는 기본 전액 환불로 관리자가 사유를 검토합니다.
- 예: 실제 결제 47,000원, 배송비 공제 4,000원 → 고객 환불 43,000원. 토스 상태는 `PARTIAL_CANCELED`이지만 전체 주문 반품은 완료되었으므로 사이트 상태는 `refunded`입니다.
- 환불 완료 시 사용 적립금과 쿠폰을 복구하고, 적립된 포인트는 회수합니다. 반환된 쿠폰은 원래 유효기간 등 사용 조건을 따릅니다.
- 반려 시 이유를 고객에게 안내하며 고객은 다시 요청할 수 있습니다.
- 배송 상태를 ‘취소’로 저장하여 실제 환불을 우회하거나, 이미 발송한 주문을 배송 준비로 되돌리는 동작을 막습니다.

## 재고와 Sanity

- `edition_claims`는 결제 승인 직전 재고를 확보합니다. DB 트리거가 같은 에디션의 경쟁 결제를 직렬화하여 중복 승인을 차단합니다. 각 에디션의 수량은 1입니다.
- 결제 완료 후 품절 유지, 결제 실패·전액 취소 또는 관리된 반품 환불 완료 시 재고 해제. 출처가 불명확한 부분 취소는 재고를 해제하지 않고 관리자 확인 대상으로 남깁니다.
- 최종 품절 = Sanity의 수동 `soldOut` 또는 DB의 결제 확보 재고. 상품·에디션 페이지의 기존 컬러 블록 표시를 재사용합니다.
- Sanity에는 결제 결과를 자동으로 덮어쓰지 않습니다. 외부 채널 판매와 웹 주문 환불이 서로의 상태를 지우는 문제를 방지합니다.
- 외부 판매 시 해당 에디션의 ‘수동 품절 · 외부 판매 / 판매 중지’를 켜고 Publish하세요. 외부 판매 취소 시 직접 해제합니다. 이미 수동으로 켜둔 품절은 이번 변경이나 웹 환불로 해제하지 않습니다.
- 웹 환불 후 재판매할 수 없는 상품은 **환불 실행 전에** Sanity 수동 품절을 켜세요. 수동 품절이 켜져 있으면 환불 이후에도 계속 품절입니다.
- 주문 생성과 첫 결제 승인 시 Sanity를 직접 조회해 수동 판매 중지를 확인합니다. 이미 승인 처리 중인 결제는 기존 결과를 조회·복구합니다. 서로 다른 판매 채널의 거래 전체를 원자적으로 묶는 기능은 아니므로 외부 판매 시 먼저 수동 판매 중지를 적용하세요.
- 품절 API 장애 시 구매 페이지는 판매를 열지 않고 오류를 표시합니다.

## 결제·알림 안정성

- API의 실제 승인 결과와 결제 키, 주문 번호, 원 결제액, 통화, 취소 잔액을 확인합니다. 관리된 부분 환불은 취소 사유의 요청 ID와 취소 금액까지 대조합니다.
- 승인 상태를 DB에서 먼저 확보하고 고정된 `return-<요청 ID>` 멱등 키로 취소합니다. 중복 클릭은 두 번째 취소 요청을 만들지 않습니다.
- 결과가 불확실하면 `reconcile`로 남겨 재고를 유지합니다. 관리 화면의 ‘토스 결과 재확인’, 기존 5분 작업, 검증된 토스 웹훅으로 복구합니다.
- 토스에 취소가 도달하지 않은 경우에는 자동 재취소하지 않습니다. 토스 상점관리자에서 원 결제와 취소 이력을 확인해야 합니다. 배송비를 남기는 수동 취소를 할 경우 취소 사유에 해당 `RET_...` 요청 ID를 포함하고 승인된 금액으로 처리해야 자동 복구됩니다. 전액 취소는 검증된 토스 결과만으로 요청을 종료합니다.
- 알림은 `shop.return_update`, `shop.return_update_admin` 이메일 템플릿을 사용합니다. 일반 알림 관리 화면에서 수정할 수 있고, 기존 재시도·발송 실패 감시를 그대로 사용합니다.
- Shop·Workshop의 토스 상품명에 `Studio OALUM ·`을 붙이고 완료 화면에 브랜드를 표시했습니다. 카드사의 승인 문자·명세서 표기를 직접 변경하는 설정은 아닙니다.

## 검증과 운영 전환

- 최신 운영 커밋 `5137e6d`에 통합하여 최근 수선 알림·HEIC 개선을 보존했습니다.
- 전체 자동 테스트 192개 통과 및 사이트 빌드, Cloudflare Functions 컴파일 성공.
- 환불 전액/4,000원 공제, 회수 전 차단, 동시 승인, 취소 응답 유실, 웹훅 중복, 쿠폰·포인트 복구, 비회원 권한, 수동 품절 우선순위 검증.
- Chrome 1440px·390px에서 고객 사유 입력, 관리자 로그인→승인, 자동 품절 컬러 블록, 재고 해제 후 구매 복구 검증. 외부 API는 가짜 응답으로 격리하여 실제 결제·이메일 발송은 하지 않았습니다.
- DB 백업으로 `0045_shop_returns_inventory.sql`을 미리 적용해 3개 판매 에디션 재고, 신규 알림 템플릿 2개, 외래키 무결성을 확인했습니다. 이미 취소된 주문의 오래된 승인 대기는 이관하지 않습니다.
- Sanity 스키마 설명 배포: https://studio-oalum.sanity.studio/
- 신규 DB 변경은 additive입니다. 이전 코드로 롤백할 때도 테이블·재고 가드는 유지하고, 접수된 반품이 있는 동안 구버전 이메일 승인 기능을 다시 열지 마세요.

실제 카드 승인·환불은 실행하지 않았습니다. 실주문으로 검증할 때는 주문의 출고 상태, 공제액, 회수 확인을 검토한 뒤 관리자가 직접 환불 실행을 선택합니다.

참고: [토스 결제 취소 API](https://docs.tosspayments.com/reference#결제-취소), [토스 웹훅](https://docs.tosspayments.com/guides/v2/webhook).
